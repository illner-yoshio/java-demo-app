# Issue5 ユーザー認証機能の追加 要件定義書

## 1. 概要

ユーザー情報を保持するRDBを作成し、ユーザー情報を管理できるようにする。
また、ログイン時に入力されたユーザーIDとパスワードと、ユーザーテーブルの情報とで一致するユーザーのみログイン可能にする 

---

## 2. 対象機能

本対応では、以下の機能を対象とする。

* ログイン機能
* RDB（MySQL）

---

## 3. 機能要件

### 3.1 RDB

* DBエンジンは、MySQLとする。
　理由：無料で使用できるため、費用面で効果があり。
* DBはユーザーテーブルを持つ。また、テーブル内には、ユーザーIDとパスワードを保持する。
* DBは、パブリックはインターネットからはアクセスできないようにする。
* パスワードは平文で保存せず、安全な方式でハッシュ化してDBに保存する。具体的な方式は設計工程で決定する。

---

### 3.2 ログイン画面におけるユーザー認証

* ログイン画面で入力されたユーザーID、パスワードが、ユーザーテーブルに登録されている情報と一致している場合はログインする
* ユーザーIDまたは、パスワードが異なる場合は、ログイン画面上にメッセージを表示する
　メイン画面への遷移はしない

## 4. 画面要件

### 4.1 ログイン画面

既存のログイン画面を使用し、変更点はなし。
ログイン認証に失敗した場合、以下のメッセージを表示する

ユーザーIDまたはパスワードが違います

---

## 5. 画面遷移

```text
ログイン画面
    ↓
認証
    ↓
【成功】→ メイン画面
    ↓
【失敗】→ ログイン画面
             ＋
       エラーメッセージ表示
```

---

## 6. 非機能要件

今回の対応では、以下を考慮する。

* ログイン情報などの機密情報を画面上に表示しない。
* ログアウト時にはログイン状態を適切に解除する。
* 既存のログイン機能に影響を与えないこと。
* Java / Spring Bootの既存構成を維持する。

---

## 7. 受入条件

以下をすべて満たした場合、本Issueの対応完了とする。

* [ ] RDSに登録されたユーザーでログインできる。
* [ ] RDSに登録されていないユーザーではログインできない。
* [ ] パスワードが一致しない場合はログインできない。
* [ ] RDSがインターネットから直接アクセスできない。
* [ ] パスワードが平文でDBに保存されていない。
